# Инженерный аудит Corne RU — этап 1

## Цель

Получить контрольную сборку без изменения раскладки и без обновления версии ZMK. Это позволит отделить проблемы BLE-конфигурации от проблем миграции или keymap.

## Результаты

### 🟢 Структура проекта

Структура подходит для пользовательской конфигурации ZMK:

- `.github/workflows/build.yml` — GitHub Actions;
- `build.yaml` — матрица сборки;
- `config/corne.conf` — общая конфигурация;
- `config/corne.keymap` — раскладка;
- `config/west.yml` — версия ZMK.

### 🔴 Принудительные роли BLE в общем конфиге

Удалены:

```ini
CONFIG_BT_PERIPHERAL=y
CONFIG_BT_CENTRAL=y
```

`corne.conf` используется обеими сборками. Одновременное принудительное включение обеих ролей в общем файле не требуется: левая и правая роли определяются shield-конфигурациями.

### 🔴 Экспериментальные BLE-флаги

Удалены:

```ini
CONFIG_ZMK_BLE_EXPERIMENTAL_FEATURES=y
CONFIG_ZMK_BLE_EXPERIMENTAL_CONN=y
```

Для контрольной стабильной сборки экспериментальные параметры исключены.

### 🟡 Усиление мощности передатчика

Пока сохранено:

```ini
CONFIG_BT_CTLR_TX_PWR_PLUS_8=y
```

Менять его будем только после проверки контрольной сборки. Более высокая мощность может улучшить связь, но увеличивает энергопотребление.

### 🟢 Сон

Сохранено:

```ini
CONFIG_ZMK_IDLE_TIMEOUT=60000
CONFIG_ZMK_IDLE_SLEEP_TIMEOUT=900000
```

Это означает переход в idle через 1 минуту и глубокий сон через 15 минут.

### 🟡 Версия ZMK

Сохранена версия `v0.2`. Обновление будет отдельным этапом после подтверждения, что контрольная версия собирается и работает.

## Критерии успешного теста

1. GitHub Actions собирает все три артефакта без ошибок.
2. Обе половины связываются после полного сброса.
3. Левая половина подключается к Windows.
4. Ввод работает после включения.
5. Ввод восстанавливается после сна.
6. Повторное включение не требует удаления устройства в Windows.
